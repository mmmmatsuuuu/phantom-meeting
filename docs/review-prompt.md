# AIで振り返る

生徒が自分の学習データを埋め込んだプロンプトをコピーし、自分の使いたい AI に貼り付けて、学習改善の壁打ちを始められるようにする。
AI をどう使い、どう改善するかは生徒に委ねる。システムは AI の API を呼ばない。

実装は `src/lib/review-prompt.ts`（プロンプトの組み立て。プロンプトの文面はここが正）、`src/lib/db/review.ts`（データの取得）、`src/components/student/review-prompt-dialog.tsx`（ダイアログ）。

## なぜ API を呼ばず、プロンプトを渡すだけにしたか

当初は、教師が生徒別の結果を AI で分析する案と、API と連携してシステム内でフィードバックまで完結させる案を検討していた。
これを「データと前提を埋め込んだプロンプトを渡すところまで」に改めた。

- 生徒は AI を使うことが前提の社会で生きていく。使い方を教師が決めるのではなく、生徒が自分で試し、自分なりの使い方を見つけてほしい
- API の費用と回数制限の設計が要らなくなる（無料枠の方針とも合う）

## 前提

- **範囲は 1 単元に固定する。** 学習改善のサイクルを単元単位で回しているため（単元のはじめに目標を立てる → 授業 → 単元テスト → できなかったところを振り返る → 次の単元）
- **どの生徒にも使える形にする。** 生徒の向き合い方は一様ではない

| 生徒の型 | 人物像 | 必要なもの |
|---|---|---|
| 点数を上げたい | 小テストは毎回受け、得点率 60〜80%。ノートは指示されたときだけ | 間違えた問題の詳細 |
| もっと知りたい | 得点率 90% 以上。授業で疑問を持ち、ノートに書き込む | 発問、自分のノートの本文 |
| 受け身・苦手 | 動画は流し見、ノートはほぼ書かない、小テストは 1 回きり | 何を聞けばいいかの手がかり |

この 3 者を 1 つのプロンプトで扱うため、目的の選択や依頼文の入力欄は設けない。代わりに、**AI から生徒に「どのようなアドバイスがほしいか」を例つきで問いかけさせる**。質問を思いつけない生徒も例から選べる。

- 教師が使うよう促すのは単元末の振り返りの時間だけ。それ以外は、生徒がつまずいたときや疑問を持ったときに自分で使う

## プロンプトの組み立て

- AI の役割（情報の教員）と進め方を指示し、そのあとに 1 単元分の学習データを続ける
- 最初の返信では、観点ごと（小テストの結果・ノートの傾向・コードの書き方）に 2〜3 文の軽い読み取りと、どのようなアドバイスがほしいかの質問だけをさせる。読み取りは、生徒が質問を考えるきっかけにするため
- 記録にない情報（単元の目標、紙で行う単元テストの結果と実施日、動画の見方）は、AI から生徒に尋ねさせる

文面で気をつけていること：

| 文面 | 理由 |
|---|---|
| 「生徒に直接語りかけて」 | ないと、AI が教師向けに第三者として書いてしまう |
| 「データの読み方」（記述式は得点率に含まない、何度でも受け直せる） | AI が得点率を誤読しないため |
| 末尾でもう一度「最初の返信は読み取りと質問だけ」と指示する | データが長いと、冒頭の指示を忘れていきなり詳しいアドバイスを書き始める AI があるため |

ChatGPT・Gemini・Claude で、最初の返信が「観点ごとの読み取り＋質問」になることを確認した。

## 載せるデータ

| データ | 載せ方 | 上限 |
|---|---|---|
| 単元の構成 | 科目名・単元名・レッスン数・出力日 | |
| 受験の推移 | レッスンごとに「日付 得点率」を並べる。未受験・小テストなしも明記 | 新しい順に 5 回 |
| 最新の受験の正誤 | `Q1○ Q2✕ Q3－`（－ は記述式） | |
| 間違えた問題 | 最新の受験で✕の問題の、問題文・自分の回答・正解 | 問題文は 100 字、10 問まで |
| 何度受けても間違えている問題 | 直近 3 回のうち、2 回以上採点されて過半数が✕の問題（番号のみ） | |
| 記述式 | 最新の受験の自分の回答と模範解答 | 各 100 字 |
| 発問 | レッスンごとに全文（レッスンに登録された発問がある場合） | |
| ノートの取り方 | レッスンごとの件数・合計文字数・動画の時刻つき件数・作成日 | |
| ノートの本文 | レッスンごとの抜粋。既定で含め、生徒が外すこともできる | 1 レッスン 300 字 |
| コード | プレイグラウンドのあるレッスンだけ。初期コードと生徒のコード・直近の実行結果。未編集なら「未編集」とだけ書く | 実行結果は 200 字 |

- **受験日を載せる理由**：「小テストから単元テストまで間があいた」「前日にまとめて受けた」など、取り組み方への助言ができるようにするため
- **記述式の模範解答を載せる理由**：自己採点で正誤の記録がない分、AI による添削の価値が大きいため
- **ノートの本文を既定で含める理由**：件数と文字数だけでは AI が言えることが限られるため。本人のデータを本人が貼るので既定で含めるが、外せるようにしている
- **コードを初期コードと生徒のコードの両方で載せる理由**：生徒のコードは教師が配った初期コードの改変で、生徒のコードだけだと教師が書いた部分まで生徒の書き方として評価されるため。差分だけを載せる案は、変更が多いと読みにくいため見送った
- **載せないもの**：氏名・学籍番号、他の生徒やクラス平均との比較（他者と比べない方針のため）。動画の視聴記録・単元テストの結果・単元の目標は記録がないため載せられない

## 字数の上限（全体で 10,000 字）

1. まず**ノートの本文**を、全レッスンで均等に短くする。それでも超えれば本文を省き、「字数の上限のため省略」と書く
2. それでも超えれば、**コードをレッスン単位で**取り込み、上限に収まるところで打ち切る。取り込まなかったレッスンには「字数の上限のため省略」と書く
   - コードは途中で切ると意味が分からなくなるため、字数を均等に削らず、レッスンごとに取り込むか省くかを決める
   - **後半のレッスンから優先する。** 後半のコードはそれまでの内容を含むことが多く、単元を通した書き方の特徴を見やすいため

## 入口

- `/quiz-results` の単元見出し（振り返りの時間に教師が案内する場所）と、ホームの単元見出しの 2 か所。押すとその場でダイアログが開く
- 小テストの提出直後やレッスンページにも置く案があったが見送った。単元に紐づかない場所だと、どの範囲のプロンプトなのかが分かりにくいため
- データはダイアログを開いたときだけ取得する（使わない生徒の分まで、ページの表示時に取得しないため）
