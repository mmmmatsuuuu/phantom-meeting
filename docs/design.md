# 授業動画配信プラットフォーム 設計ドキュメント

## プロダクト概要

「情報Ⅰ」の授業で使用する動画を生徒に配信するプラットフォーム。
動画を「ただ見るだけ」で終わらせず、理解を深め、思考を広げる場を提供する。

---

## 解決したい課題

- 生徒が動画を受け身で視聴するだけで終わっている
- 動画の内容を超えて知識・思考を深める機会がない

---

## ロール設計

| ロール | 登録方法 | 利用開始 |
|---|---|---|
| `admin` | DBに直接設定（開発者自身） | 即時 |
| `teacher` | Google登録 → adminがDBで直接ロールを変更 | 変更後 |
| `student` | Google登録 | 即時 |

承認申請フローの UI（`/admin/users`）は運用されず機能していなかったため撤去した。
teacher への昇格は admin が Supabase 上で `profiles.role` を直接書き換える運用のみ（ウェイトリストに UI 化タスクあり）。

---

## コアユーザーフロー

```
動画視聴
  ↓
発問に回答（探究への入口）
  ↓
メモを残す（クローズド：自分だけ見える）
  ↓
任意で投稿（クラスに共有）
```

## UIコンセプト

### 名前

**ruminy**（ルミニー）。正式なサイト名で、ruminate（反芻する、じっくり考え直す）からの造語。`phantom meeting` はコードネームで、リポジトリ名などはそのまま残す。

コードネームの由来はポッドキャスト「まぼろし会議」で、教養系のポッドキャストが増える一方で「ファスト教養」のように消費されて終わっている、もっと深い学びにつなげたい、という話がきっかけになった。ruminate は、飲み込んだものを噛み直すことと、考え直すことの両方を意味するため、この問題意識をそのまま名前にできる。

### 用語：画面の「ノート」と、DB・コードの `memos`

レッスンで生徒が書くものは、ひな形を読み込んで 1 時間かけて書き進めるもので、メモの域を超えているため、**画面上は「ノート」と呼ぶ。**
一方、**DB とコードは `memos`（`memo`）のまま残す。**

| 画面 | DB・コード |
|---|---|
| ノート | `memos` テーブル、`Memo` 型、`/api/memos`、`src/lib/db/memos.ts` など |
| ノートのひな形 | 未実装（テンプレート。実装時に名前を決める） |

- DB まで改名しない理由：テーブル・RLS・集計用の関数・型・API・CSV の列に広く使われており、本番 DB での改名と作り直しの危険に、名前が変わる以外の得がない
- コードの型だけ `Note` にする案も採らない。DB とコードの間で名前が 2 つになり、かえって混乱する
- 画面の文言は、生徒画面だけでなく教員画面・ダッシュボード・エクスポートも「ノート」にそろえる

### キャッチコピー

**飲み込んで終わりにしない。反芻する学習サイト**（ログイン画面に出す）

### コンセプト

**飲み込んで終わりにしない。動画で学び、ノートで噛み直し、小テストで確かめる。**

| 段階 | 役割 |
|---|---|
| 動画で学ぶ | 内容を知る |
| ノートで広げ、深める | 動画の内容を超えて、自分の考えを足す |
| 小テストで確かめる | 知識の定着を確認する |

### 解決したい問題

- 多くの生徒が熱心にノートを取っているが、話を追うだけで精一杯で、動画の**写経**になっている
- 発問は、動画の内容を超えて考えるきっかけのはずだったが、授業内にその余裕がなく形骸化している

原因は生徒の意欲ではなく、**記録に余裕を使い切っていること**にある。他の授業でプリントが担っている役割を、ノートのテンプレートで担う。

### ノートのテンプレート

教師がレッスンごとに、穴埋めと発問を含むプリントのようなテンプレートを用意する。生徒はそれをノートのエディタに読み込み、編集して自分のノートにする。

| 決定 | 理由 |
|---|---|
| **テンプレートを tiptap の文書として読み込む** | 穴埋めも発問も図も、同じエディタで扱える。専用の入力部品を作らずに済む |
| **生徒はテンプレートのどこでも書き換えられる** | 自分のノートなので、書き方は生徒に任せる |
| **穴埋めの答えは表示せず、採点も記録もしない** | 答えは動画にある。確認は小テストの役割で、ノートまで点数にすると埋めること自体が目的になる |
| **発問はテンプレートの中に置く** | 独立した欄だと後回しにされる。穴埋めの流れの中で目に入る場所に置く |
| **図や画像を使えるのは教師が用意したものだけ** | 外部の画像を許すと、ノートを開くたびに外部へ通信が発生し、画像が差し替えられても気づけない。生徒のアップロードを許すと、不適切な画像や保存容量の管理が必要になる |
| **テンプレートは JSON で一括読み込みする** | 作成の負担が一番の課題。授業資料から AI で下書きを作り、教師が直す（小テストと同じ流れ） |
| **テンプレートがないレッスンは今のノートのまま** | 既存のレッスンをすぐに作り直す必要がない |
| **動画を隠さない** | 授業内の時間に余裕がない。見ながら穴埋めし、書きたいときに自分で止める |
| **クラスへの投稿は廃止する** | テンプレートを使うと、穴埋めの答えが同じになり、似た投稿ばかりが並ぶ。現状でも自分で調べた内容を投稿する生徒はおらず、投稿はほとんど見られていない。廃止は別ブランチで行う |
| **ノートは 1 レッスンに 1 つを基本とし、複数も書ける** | テンプレートを埋めた 1 枚にまとまるのが自然。ただし 1 枚に収まらないこともあるため、機能としては複数を残す |

### 実装に必要な変更

- **テンプレートの保存先**：レッスンごとの tiptap JSON を置く場所と、教師の編集画面、JSON 読み込みを追加する
- **読み込み**：プレイグラウンドの「メモに保存」ボタン（画面の文言は「ノートに保存」に変える）が使っている `prefillContent` の仕組みをそのまま使える
- **ノートの更新**：現在のノートは保存すると入力欄が空になり、後から編集できない。テンプレートは1時間かけて書き進めるものなので、保存したノートを開き直して続きを書く機能が必要になる（RLS は本人の更新を許可済みで、更新 API と画面を追加する）
- **画像の制限**：エディタは画像の表示に対応済みで、貼り付けは拒否している。ただしサーバー側の検証がないため、保存時にテンプレート由来の画像だけを許可する。`/api/images/upload` も生徒が呼べるので教師のみに変更する

### マスコット

**片方の頬をふくらませて、もぐもぐ反芻しているヤギ。** 濃紺インクの線画で描く。

| 決定 | 理由 |
|---|---|
| ヤギ | 反芻する動物で、名前（ruminate）と一致する。「紙を食べる」動物としても知られ、紙とノートの見た目につながる |
| 片頬のふくらみを特徴にする | 反芻の「飲み込んだものを口に戻して噛み直す」様子を表し、コンセプトと一致する。左右非対称の輪郭は、小さくしても見分けやすい |
| 噛んでいるのは本の欠片。本の角は半円形にかじり取られている | 学んだものを噛み直していることが一枚の絵で伝わる。破れ目より歯形のほうが、小さくしても欠けが読める |
| 濃紺インクの線画 | ノートの余白の落書きのようで、紙とインクの画面に溶け込む。3 案（線画・切り絵・色付きの絵本調）を比べて決めた（[mockups/mascot.html](mockups/mascot.html)） |
| 大きい場所は全身、小さい場所は顔だけ | 1 枚の絵で全サイズを賄うと潰れる。ファビコンを本の形にする案は、学習系のサービスにありふれていて区別がつかないため採らなかった |
| 1 画面に 1 匹。動画の視聴中・ノートの記入中・教員画面には出さない | 集中の邪魔をしない。教員画面はヘッダーの顔だけにする |
| 点数や回数で表情を変えない。小テストの結果画面には出さない | 採点や記録をしないノートの方針と同じく、点数と結びつくと比べるものになる |

出す場所はログイン、ヘッダー、ノートの空欄、404、何もないときの表示。一覧と生成 AI への指示文は [mascot.md](mascot.md)。

### 見た目の決まり

ノートとプリントの比喩で統一し、飾りは足さない。

| 項目 | 決定 | 理由 |
|---|---|---|
| 配色 | 藁半紙の紙、インクの濃紺、鉛筆の灰色、赤ペンの朱（値は下表） | 色に役割を持たせる。朱は赤ペンとして、**答え合わせと、直すところ・気をつけるところ**（コードのエラー、正答率の低い問題、公開停止など）にだけ使う |
| 区切り | カードの枠と影をやめ、罫線で区切る | 情報を箱に入れず、ノートの行として並べる |
| 一覧 | **レッスン一覧は、単元ごとに 1 枚のルーズリーフにする**（パンチ穴・余白線・罫線。行の高さを罫線の間隔にそろえる） | 同じ形の箱が並ぶと強弱が消え、目次の形だけでは味気ない。単元を 1 枚の紙として綴じていく見た目が、ノートの比喩に合う |
| 角丸 | 使う場合も 2px まで | 紙と文具の質感に合わせる |
| 絵文字 | UI には使わない | 意味は文字と形で伝える |
| 書体 | **操作と状態は端末標準のサンセリフ、内容は Klee One**。内容とは、レッスン名・単元名・見出し・ノートの本文など先生や生徒が書いたもので、リンクであっても内容として扱う | ボタンなどの操作部品はかっちりと、生徒が書く内容は手書きのように見せ、ノートらしさを出す。Klee One は教科書体（硬筆の楷書）を元にした書体で、生徒が見慣れた字形のため読みやすい。手書き風の 3 書体を比べて選んだ（[mockups/type.html](mockups/type.html)）。SIL Open Font License。日本語は文字ごとに分割して配信されるため、使った文字の分だけ読み込まれる |
| 入力欄 | **方眼の用紙**（背景より一段明るい `#f8f7f2` に、ごく薄い 16px の方眼） | 背景の紙と見分けがつき、書ける場所だと分かる。罫線と違い、図や表が混ざっても違和感がない。方眼の線は文字の読みやすさを妨げないよう、ほとんど気づかない程度に薄くする |
| 行の高さ | **方眼の目（16px）の倍数にそろえる** | 本文と見出しの行の高さを 32px にそろえ、余白も 16px の倍数にすると、どの行も方眼の線にそろう。図や表は高さが自由なのでずれるが、方眼なら気にならない |
| 教員画面 | 同じ配色で、飾りを足さず情報量を優先する | 教員は比喩より一覧性を必要とする |
| 小テスト | **答案用紙にし、答え合わせは赤ペンの○とレ点で示す。** ○とレ点は問題番号の左の欄に書き、文字にかけない。正解の選択肢には「正解」と添える。得点は赤字で出すだけで、丸で囲まない | 実際の採点でも、印を文字にかけないよう指導されている。得点を目立たせると比べるものになる |
| コードエディタ | **方眼にしない。** 用紙の色と枠だけ | ノートではないため。方眼はノートと入力欄の印にとどめる |
| 画面の幅 | **PC を前提とし、スマホには対応しない** | スマホでの利用は想定していない。動画とノートを横に並べる画面を優先する |
| ダークモード | **対応しない** | 紙の質感を暗い配色で出すのは難しい。代わりに、純白を避けた紙の色とコントラストを抑えた配色で、夜でもまぶしくないようにする。本文と背景のコントラストは 4.5:1 を下限とする |

#### 配色

紙の色は、学校のプリントの藁半紙をもとに、黄土色を抑えた暖かい灰色にした。白い紙・藁半紙・再生紙・夜向けの暗い紙を比べ、藁半紙の黄色みを 4 段階で調整して選んだ（[mockups/palette.html](mockups/palette.html)）。

| 役割 | 値 | 背景とのコントラスト比 |
|---|---|---|
| 紙（背景） | `#efede6` | |
| 面（入力欄・案内の背景） | `#e5e2d8` | |
| インク（本文・ボタン） | `#1d2b3f` | 12.2 |
| 鉛筆（補足の文字） | `#60605b` | 5.4 |
| 罫線 | `#d6d3c7` | |
| 赤ペン（答え合わせ・エラー・注意） | `#b93a2b` | 4.8 |
| 付箋（「続きから」の背景） | `#efe4b4` | インク 11.2・補足の文字 `#5c5a50` 5.4 |

- インクはヤギの線と同じ色にした
- 付箋の黄色は、目次の先頭の「続きから」にだけ使う。紙と明るさが近いため、色味だけで区別し、上端ののりの帯とめくれた角で付箋だと分かるようにした
- 純白を使わないことで、夜でもまぶしくないようにした
- ヤギの絵は内側が白く塗られているため、乗算で重ねて紙の色を透かす

モックは [mockups/student.html](mockups/student.html)。ブラウザで直接開いて操作できる。
