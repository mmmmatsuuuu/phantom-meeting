# 機能設計

各機能が何をするかと、そう決めた理由。名前・コンセプト・見た目の決まりは [design.md](design.md)、処理をどこに置いているかは [processing-map.md](processing-map.md) を参照。

画面上の「ノート」は、DB とコードでは `memos`（理由は [design.md](design.md) の「用語」）。

---

## 共通

### ロール
- 生徒と教師は Google アカウントでログインする。登録した時点では生徒で、教師にするときは admin が Supabase 上で `profiles.role` を直接書き換える
- 承認申請の画面（`/admin/users`）は運用されず機能していなかったため撤去した（`profiles.is_approved` 列は DB に残るが使っていない）

### エディタ（ノート・ひな形・小テスト）
- tiptap。ツールバーは太字・斜体・見出し・箇条書き・番号付き・コード・コードブロック・引用・リンク・表。記号やアイコンではなく、文字のボタンで示す
- コードブロックはシンタックスハイライトつき（Python・JavaScript・C・HTML・CSS）
- 表は、行と列の数をグリッドで選んで挿入し、あとから行と列を足したり消したりできる
- **画像**：貼り付けると ImageKit にアップロードして URL で保存する。貼り付けられるのは教師だけ（小テストとノートのひな形）。挿入した画像はドラッグで幅を変えられる
- 拡張の設定はすべてのエディタと表示で共通（`lib/tiptap/note-extensions.ts`）。ひな形をそのままノートに読み込み、同じ見た目で表示するため

### 画面遷移
- リンクを押した瞬間に、画面上部にローディングバーを出す（`nextjs-toploader`）。App Router のデータ取得による待ち時間に、押したことが伝わらず二度押しされるのを防ぐ

## 生徒向け

### 目次（ホーム `/`）
- 単元ごとに 1 枚のルーズリーフにレッスンを並べる。新しい単元を上にし、単元内のレッスンは授業の順
- 各行に、ノートの有無（ノートあり）と小テストの得点（赤ペン）・未受験を出す
- 科目ごとに折りたためる。開閉の状態は Cookie に残す
- 単元の見出しから「AIで振り返る」を開ける。自由制作の課題は、表示する単元の中にカードで出る
- 教師・管理者にも出す（生徒にどう見えるかを、自分のデータで確かめられるようにするため）

### レッスン（`/lessons/[lessonId]`）
左に動画と小テスト、右にノート（とコード）を並べる。PC での利用を前提にしている。

**動画**
- YouTube の埋め込み。動画は隠さない（授業内の時間に余裕がないため、見ながら穴埋めし、書きたいときに自分で止める）

**ノート**
- **クローズド**：本人だけが読み書きできる（教師は閲覧できる）
- **ひな形**：教師がレッスンごとに用意した、穴埋めと発問を含むプリントのようなひな形を読み込み、穴を埋めたり、自由に書き換えたりする。答えは表示せず、採点も記録もしない。ひな形がないレッスンは白紙から書く（なぜひな形を使うかは [design.md の「ノートのテンプレート」](design.md#ノートのテンプレート)）
- **続きを書ける**：最後に更新したノートを開く。保存しても入力欄を空にしない。保存していない変更があるままページを離れると確認を出す
- **1 レッスンに 1 つが基本**：1 枚に収まらないときは「＋ 新しいノート」で複数書ける
- **見た目**：方眼の用紙に Klee One。行の高さと余白を方眼（16px）の倍数にそろえる
- **画像**：生徒は画像を入れられない。使えるのは、ひな形に教師が入れた画像だけ（保存時にサーバーで検証）
- **大きさの上限**：ノートとひな形は、それぞれ 256KB まで（保存時にサーバーで検証）。動画 1 本分を詰めたプリントは 40KB 前後で、生徒が書き足しても収まる。教師の画面がクラス全員分のノートを一度に取得するため、上限を設けている
- 動画の時刻（`timestamp_seconds`）の記録は画面から外した。列は残っており、以前のノートでは教師の画面に時刻が出る

**小テスト**
- 役割は理解の確認（正誤・採点）。ノートでは採点しない
- 問題形式は選択式・記述式・並び替え。選択式と並び替えはサーバーで自動採点し、記述式は模範解答を見て自己採点する（得点には含めない）
- **答案用紙の見た目**：選択肢は記号（ア・イ・ウ…）を丸で囲んで選び、並び替えは短冊をドラッグで動かす（@dnd-kit）
- **赤ペンの答え合わせ**：○と×は問題番号の左の欄に書き、文字にかけない。正解の選択肢に「正解」と添え、解説と模範解答を赤ペンで示す。得点は赤字で書くだけで丸で囲まない
- 何度でも受け直せる。提出のたびに、各問の回答と正誤を `quiz_attempt_answers` に保存する（記述式の `is_correct` は null）
- 提出の直後に、ほかに要復習のレッスンがあれば件数と小テスト結果への導線を出す

**コーディングプレイグラウンド**（`lessons.enable_playground` が有効なレッスンだけ）
- プログラミング単元の PRIMM（予想 → 実行 → 調査 → 改造 → 作成）の授業を支える。ゼロからコードを書く場所ではなく、教師が用意したコード例を動かして改変する場所
- ノートの横のインデックスから切り替える。コード例ごとにタブがあり、CodeMirror 6 のエディタ・実行ボタン・コンソールを並べる
- 編集内容と直近の実行結果は「保存」を押したときだけ保存し（`code_states`）、次に開いたときに戻す。未保存のタブには ● を付け、ページを離れるときに確認を出す
- 「ノートに貼る」：コードと直近の実行結果をコードブロックにして、開いているノートの末尾に追記し、ノートに切り替える
- 「初期コードに戻す」：確認のあと、教師が配った初期コードに戻して保存する。授業中に触りすぎて戻せなくなったときの救済
- Cmd/Ctrl + Enter で実行、Tab / Shift+Tab でインデント
- 実行結果は直近 8,000 字まで（無限ループなどで出力が際限なく増えないように）

実行はすべてブラウザ内で行う。

| 決定 | 理由 |
|---|---|
| サーバーでコードを実行しない | 任意のコードを実行するセキュリティの危険と、サーバーの費用を避けるため |
| Python は Pyodide をメインスレッドで動かす（CDN から読み込む） | npm のパッケージ本体は Node.js 向けの動的 require を含み、バンドルできないため |
| Web Worker + SharedArrayBuffer を使わない | COEP ヘッダーが必要になり、同じページに埋め込む YouTube と衝突するため |
| Python の `input()` は、実行前に構文木を書き換えて `await input()` にする | Worker なしで、コンソールの入力欄から入力を待てる。生徒は普段どおり `input()` と書けばよい。入力した値はコンソールに残り、ノートに貼ったときに何を入れたか分かる |
| Python の無限ループは、ループの先頭に経過時間の確認を差し込み、10 秒で止める | メインスレッドで動かすため、止めないとページが固まる。内包表記など、ループの構文を使わない重い処理は検知できない |
| JavaScript はサンドボックスの iframe（`allow-scripts allow-modals`）で動かし、10 秒で iframe ごと破棄する | `allow-same-origin` を付けないので、Cookie や画面に届かない。`prompt()` はブラウザのダイアログのまま（JavaScript には構文木の書き換えに使える仕組みが標準でないため） |
| CodeMirror 6 | Monaco Editor より軽く、Chromebook などでも動作が軽い |
| 標準ライブラリだけ（pip install はできない） | 情報Ⅰの基礎としての範囲。これを超える用途は、別のコーディング環境を使う |

### ノート一覧（`/memos`）
- 全レッスンのノートを、科目 → 単元 → レッスンの階層で並べる。各レッスンに動画へのリンクを付ける
- 左に目次を固定で出し、いま見ている節を強調する
- Markdown で書き出せる（レッスン・単元・科目の単位）

### 小テスト結果（`/quiz-results`）
- 自分の受験履歴を、科目 → 単元 → レッスンの階層で並べる（未受験のレッスンは出さない）
- レッスンごとに直近 3 回の最高と平均の得点率、単元ごとにその平均を出す
- 受験ごとに日時・得点・設問ごとの正誤（○✕－）を開いて確かめられる。回答の詳細がない古い記録は「詳細な回答記録なし」と出す

### AIで振り返る
- 1 単元分の学習データを埋め込んだプロンプトを作り、生徒が自分の使いたい AI に貼り付けて振り返りの壁打ちをする。システムは AI の API を呼ばない
- 入口は `/quiz-results` とホームの単元見出し。ダイアログでプレビュー・文字数・「ノートの本文を含める」の切り替え・コピー・注意書きを出す
- 仕様と決めた理由は [review-prompt.md](review-prompt.md)

### プロフィール（`/profile`）
- 学籍番号と備考を自分で編集する。表示名は Google アカウントの名前で、編集できない

## 教師向け

### 教師ページ（`/teacher`）
- 教師の機能の入口。コンテンツ管理・自由制作・分析・生徒一覧・データエクスポートを並べる。右上のメニューにも同じ項目を出す

### コンテンツ管理（`/teacher/contents/[subjectId]`）
- 科目ごとにページを分け、上部の科目タブで切り替える。`/teacher/contents` を開くと先頭の科目に移る
- 単元は新しい順に並べ、「＋ 単元を追加」は単元の一覧の上に置く。単元内のレッスンは授業の順
- 単元の行の「レッスン追加」から、YouTube の URL と初期コードを登録する
- レッスンごとに、ノートのひな形・小テスト・プレイグラウンドの初期コードを編集する
  - **ノートのひな形**（`/teacher/lessons/[lessonId]/note-template`）：生徒のノートと同じ見た目で書く。生成 AI に下書きを作らせて JSON で読み込める（[note-template-json.md](note-template-json.md)）
  - **小テスト**（`/teacher/lessons/[lessonId]/quiz/new`）：1 問ずつ書くほか、JSON で一括インポートできる（[quiz-json.md](quiz-json.md)）
  - **初期コード**（`/teacher/lessons/[lessonId]/code-snippets`）：タイトル・言語・コードを複数登録し、並び替える
- レッスンを消すと、ノート・小テスト・回答なども一緒に消える（確認を出す）
- **発問**：レッスン登録のフォームから発問の欄を外した。発問は、ひな形の中に「考えてみよう」として置く。独立した欄だと後回しにされ、形骸化したため（既存の `questions` のデータは、AIで振り返るのプロンプトで使っている）

### 分析（`/teacher/analytics`）
- **単元別**：学年・クラス・科目を選ぶと、レッスン × 設問の平均正答率をヒートマップで出す。小テスト・単元・科目ごとの平均も出す
  - 小テストの平均は、記述式を除く全回答の正答率。単元と科目の平均は、その中の小テストの平均を単純平均したもの（小テストごとに重みをそろえる。回答のない小テストは除く）
- **レッスン別**：学年・クラス・科目・レッスンを選び、小テスト・コード（プレイグラウンドのあるレッスンだけ）・ノートのタブを切り替える。タブは開いたときだけ取得する
  - **小テスト**：生徒 × 設問の回答の一覧。得点、設問ごとの○✕（ホバーで生徒の回答と正解）、記述式の回答、ノートの件数を出す。生徒名から個人詳細に移れる
  - **コード**：生徒ごとのカードに、そのレッスンの全コード例（コード・直近の実行結果）を縦に並べる。未編集は「未編集」と出す
  - **ノート**：生徒ごとのカードに、ノートを時系列で出す。ノートを書いた人数と合計件数も出す。ノートのない生徒もカードに含める
  - 集計は各生徒の**最新の受験だけ**を対象にする（データエクスポートと同じ）
- **生徒別**：表示名・学籍番号で絞り込める生徒の一覧から、個人詳細に移る

### 生徒一覧・個人詳細（`/teacher/students`、`/teacher/students/[userId]`）
- 一覧：学籍番号・表示名・ロール・備考。表示名と学籍番号で検索・並べ替えができ、学籍番号と備考はその場で編集できる
- 個人詳細：小テストの受験数・平均得点率・要復習の数・ノートの件数のまとめと、単元ごとのレッスン別の表（最新の得点率・受験回数・ノートの件数）

### データエクスポート（`/teacher/data-export`）
学年・科目・単元を選び、単元単位で CSV を書き出す。画面に、生成 AI に貼り付けて使う分析用のプロンプトを出し、コピーできる（API 連携はしない）。学籍番号・氏名は含めない。

- **小テスト結果**：各生徒の最新の受験を対象に、設問ごとの正答率（学年全体とクラス別を横に並べる）、誤答の内訳、記述式の回答（ランダムに 3 件）
  - 誤答の内訳は、正答率 60% 以下の選択式だけに絞る。それより高い設問は理解が定着しているとみなすため。並び替えは誤答が並べ方の組み合わせになり、内訳として読みにくいため含めない
- **ノート**：レッスンごとに、ノートを書いた生徒から各クラス 2 人ずつ（10 人に満たなければ 10 人まで追加）を選び、1 人分を「／」で結合して 300 字で切り詰める
  - クラスごとに選ぶのは、クラスの偏りを避けるため

## 自由制作（`/maker`、`/teacher/maker`）

プログラミング単元の統合問題に代わり、生徒が作るものを自分で決めて制作・提出・共有する課題。年 1 回程度の特設イベントで、次年度以降も使う保証がないため、レッスンとは独立した画面とテーブルで作る。

- **教師**
  - 課題の作成：詳細、表示する単元、初期コード、AI に相談するプロンプト、作品例を設定する（言語は Python のみ）
  - 公開状態：下書き / 受付中 / 受付終了
  - 作品展の開放：クラスごとに切り替える。開放するまで、生徒には自分以外の作品が返らない（RLS）。提出前に他の生徒の作品を見られないようにするため
  - 提出状況（`/teacher/maker/[eventId]/submissions`）：クラスごとに全生徒の状態（提出済み / 公開停止中 / 下書き中 / 未着手）を一覧し、生徒を選ぶと課題設定・説明・コードを確かめて実行できる
  - 公開停止：問題のある作品を個別に停止・再開する
  - 提出物の JSON 書き出し（氏名・課題設定を含む）
- **生徒**
  - 目次の単元内のカードから課題を開く
  - 課題設定（教師だけが見る）、作品名、説明、コードを書き、保存・提出する。保存はボタンを押したときだけ
  - 提出には学籍番号が必要。作者として学籍番号を出す。提出後に公開中の作品を更新するには、もう一度提出する
  - クラスが開放されると、作品展で作品を見て実行できる。作品は「実行」を押すまで動かない
  - 作品展はクラス単位で出し（最初は自分のクラス）、学年・組を選んで切り替える。全員分を一度に取得すると RLS の判定と転送量が増え、DB の負荷が大きくなるため。教員の作品は作品展に出さない
  - 作品を選ぶとモーダルで説明・実行・コードを出す（一覧の下に出すと、作品が多いときにスクロールが大変なため）
- **実行環境**（`src/lib/maker-python-runner.ts`）
  - 他の生徒のコードを動かすため、レッスンのプレイグラウンドとは別に隔離した環境を用意した。`allow-same-origin` なしのサンドボックスの iframe 内の Worker で Pyodide を動かし、CSP で外部への通信を遮断する。Cookie や画面には届かない
  - サンドボックス内ではブラウザのキャッシュが効かないため、親のページで取得した Pyodide の資材を iframe に渡す
  - 無限ループは 10 秒で実行環境ごと破棄する（`input()` の入力待ちの間は計測を止める）
  - `input()` は `def` の中でも使える。ただし JSPI に対応していないブラウザでは、トップレベルでだけ動く

**廃止の手順**：必要なら提出物を JSON で書き出し、マイグレーション `20261101000001_maker_festival.sql` の冒頭の drop 文を新しいマイグレーションとして適用する。あわせて `src/app/(student)/maker`、`src/app/(teacher)/teacher/maker`、`src/app/api/maker`、`src/components/maker`、`src/lib/db/maker.ts`、`src/lib/maker-*`、目次のカード（`subject-list.tsx` の `makerEventsByUnit` とホームの取得処理）、教師ページのカードを削除する。

## 廃止・見送りした機能

| 機能 | 状態 | 理由 |
|---|---|---|
| クラスへの投稿 | 2026年11月に画面と API から外した。`posts` テーブルは別の PR で削除する | ひな形を使うと穴埋めの答えが同じになり、似た投稿ばかりが並ぶ。自分で調べた内容を投稿する生徒がおらず、投稿はほとんど見られていなかった |
| 小テストの完了ゲート（終えるまで投稿を隠す） | 投稿と一緒に外した | 投稿を廃止したため |
| 発問の独立した欄 | ひな形の中に移した | 後回しにされて形骸化したため |
| 学習状況のまとめ・「つぎにやること」（ホーム） | 2026年11月に外し、部品も削除した | あまり使われていなかったため（まとめの集計は個人詳細で使う） |
| いいね | 見送り | いいねの数が見えると受けを狙った投稿が増え、正直な気づきが書きにくくなる。過激な内容ほど注目を集める SNS のような歪みが生まれる |
| トロフィー・実績、匿名のコメント | 計画から削除 | 今のところ必要性を感じていないため。コメントは投稿を前提にしていた |
